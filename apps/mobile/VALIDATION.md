# 검증 결과

## 2026-09-16 화면 오류 수정 · 앱 1.0.2

- 로그인 화면의 빈 오류 메시지, 설정 화면의 빈 오류/저장 안내, 공통 UI의 빈 보조문구/동작명/출처 조건이 `View`에 빈 문자열을 전달하던 문제를 수정했습니다.
- 변경 전 실제 React Native Web `View`와 React DOM 렌더러로 화면을 렌더링해 첨부 화면과 같은 `Unexpected text node` 로그를 재현했습니다. 아이콘·기기 safe-area·앱 상태/탐색만 테스트 대역으로 대체했습니다.
- 변경 후 로그인 초기 상태, 설정 초기 상태, 오류 메시지가 있는 로그인, 빈 공통 안내 문구, 값이 있는 공통 안내 문구의 5가지 렌더링 검사를 통과했습니다. 해당 오류 로그는 0건이며 내용이 있는 안내 문구는 계속 표시됩니다.
- `npm run typecheck` 통과.
- SDK/라이브러리 의존성과 기존 API 클라이언트·데이터 처리·cron은 변경하지 않았습니다.
- 실제 iPhone/Android의 렌더링과 로그인 검증은 아직 필요합니다. 이번 확인은 브라우저 기기 테스트가 아닌 React DOM 서버 렌더링 검사입니다.

## 2026-09-15 SDK 57 호환성 검증 기록

작업일: 2026-09-15 · SDK 57 호환 수정본 1.0.1

Expo 57.0.22 / React Native 0.86.3 / React 19.2.3 / TypeScript 6.0.3. 모바일 패키지에만 적용했습니다. Expo SDK 55~57의 변경 사항을 확인하고, 관련 네이티브 라이브러리를 SDK 57의 호환 버전으로 함께 갱신했습니다. 폐지된 Android `edgeToEdgeEnabled` 설정을 제거하고 시작 화면은 `expo-splash-screen` 플러그인으로 옮겼습니다. TypeScript 6에서 필요한 테스트용 Node 타입도 명시했습니다.

테스트에는 KST 날짜 경계, 시장폭 결측, 0 수급과 누락 구분, fallback 표시, Pulse 환산/세션 분리, 중복 기록 선택, 휴장일/주말 제외, 업종 응답, 서버 주소 검증, 로그인 검증 전 쿠키 미생성, 만료 세션 차단, 다른 서버로 쿠키 전송 차단, HTML/인증/미배포 오류 구분, 기존 tsconfig 보존과 재실행 안전성을 포함했습니다.

번들 생성은 네이티브 설치 파일 빌드나 실기기 검증을 대신하지 않습니다. 파일을 적용한 뒤 기존 접근 코드로 로그인하고 날짜별 조회·차트 터치·앱 백그라운드 복귀를 확인하세요.

SDK 57 변경 범위는 `apps/mobile`의 의존성·앱 설정·타입 설정·버전 표시와 실행 안내입니다. 기존 모바일 API 클라이언트, 데이터 모델, 통합 스크립트, 아이콘은 이전 제공본과 동일한 것을 확인했습니다. 앱이 사용하는 기존 조회 API의 구현·DB·KIS 인증·수집 cron은 수정하지 않았습니다. `integrate:parent`를 실행하면 해당 PC의 기존 tsconfig에 제외 항목 하나를 추가합니다.
