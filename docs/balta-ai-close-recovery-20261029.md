## 원인과 수정

실패 실행 [40712526823](https://github.com/baltazzadesign/market-dashboard/actions/runs/40712526823)은
10/29 00:06 KST, [40724455324](https://github.com/baltazzadesign/market-dashboard/actions/runs/40724455324)는
10/29 01:17 KST에 시작했다. 기존 main은 실제 실행일의 `now.date`와 시각만 사용했다.
16:30 제한이 try/catch 바깥에 있어 상세 DB 실패 기록 없이 `Unexpected worker failure`로 종료했다.

변경 내용:

1. 예약식과 **최초 run.created_at**에서 예약 회차를 결정해 `--date=YYYY-MM-DD`로 전달한다.
   재실행 시 바뀌는 run_started_at이나 러너의 현재 날짜는 평가일 선택에 사용하지 않는다.
2. 정책은 최초 생성 시각 이전의 가장 가까운 해당 cron 회차, 최대 12시간 지연이다.
   GitHub는 cron의 원래 발생 타임스탬프를 제공하지 않으므로 이는 명시적 운영 정책이다.
   12시간 창 밖은 실패시키며 수동 날짜 지정으로 처리한다. 하루 이상 늦게 **생성된** 실행이 다음 회차와 겹치는 경우,
   GitHub 정보만으로 원래 회차를 식별할 수 없다. 그 경우 자동 추론을 신뢰하지 말고 날짜를 지정해야 한다.
   이미 생성된 작업의 러너 대기 및 재실행 지연은 최초 생성 시각을 고정해 처리한다.
3. 마감 제한은 `대상일 16:30 KST`라는 절대 시각과 비교한다. 전날 평가를 다음 날 새벽에 실행할 수 있다.
   가격의 provisional 여부도 대상일 18:30과 비교한다. 공식 확정 종가라고 표시하지 않는다.
4. 대상일의 주말/휴장일은 건너뛰며 직전 거래일로 임의 이동하지 않는다.
   2026 외 연도는 검증된 휴장일 목록 및 `MARKET_CALENDAR_VERIFIED_YEARS` 설정 없이는 거절한다.
   추가 휴장은 `MARKET_HOLIDAYS`를 사용하고 실제 시장 세션은 KIS 일별 지수로 확인한다.
5. 수동 실행은 날짜 필수, dry_run 기본 true. 늦은 오전 실행은 저장된 원본 후보만 검사하고 후보를 재생성하지 않는다.
6. 초기화/경계 실패를 포함해 대상일·실제시각·run ID/attempt·SHA·단계·분류·안전한 코드 위치를 기록한다.
   임의 오류 본문, 응답 body, 토큰은 기록하지 않는다. 데이터 결측과 저장 검증 실패는 종료 코드 1이다.
7. 기본키 충돌은 ignore-duplicates로 처리하며 새 쓰기는 정확한 키/내용을 다시 읽어 검증한다.
   가격을 먼저 검증·저장한 뒤 성과를 계산한다. 통신 단절 후 재시도와 중복 실행은 기존 값을 보존한다.
   기존 workflow 단일 concurrency와 bounded retry를 유지한다.
8. 공급자 시가와 기존 시가가 달라지면 가격 기준을 확인할 수 없으므로 해당 종목/후보의 신규 계산을 중단하고 `priceRevisionConflicts`를 기록한다.
   시가가 동일하고 고가·저가·종가가 변경된 경우에는 기존 OHLC 전체를 그대로 사용하며 차이를 `priceRevisionDetails`로 기록한다.
   수정주가의 서로 다른 기준을 섞거나 기존 값을 덮어쓰지 않는다.
9. dry_run은 연구 테이블·run log·공유 KIS 토큰에 쓰지 않는다. 토큰 만료 시 갱신하지 않고 실패한다.
   비밀키를 사용하는 연결 검사는 PR에서 자동 실행하지 않고 별도 수동 실행으로 제한한다.

주의: `balta_ai_run_log`는 날짜·phase별 한 행인 기존 구조다. 마지막 상태를 갱신하며 모든 시도 이력을 DB에 누적하는 구조는 아니다.
이미 complete인 상태는 이후 실패로 덮어쓰지 않으며 실패 시도는 Actions 로그에 남는다.
DB 장애로 run log 저장도 실패하면 콘솔에 그 사실을 기록한다. 완전한 시도별 원장은 별도 승인된 스키마 작업이 필요하다.

## 승인 후 복원 순서 (아직 실행하지 않음)

1. 운영 배포 ID/SHA와 main 변경 여부를 다시 읽고 회원 화면 보존 manifest와 비교한다.
   main 병합은 Git 연동 운영 자동배포를 유발할 수 있으며, 다음 예약 연구 쓰기도 활성화한다.
   **병합과 그에 따른 운영 배포·예약 실행을 명시적으로 승인받아야 한다.**
2. 가격·성과·벤치마크·시뮬레이션·후속관찰·후보의 기존 키와 내용 해시를 읽기 전용으로 확보한다.
   투자자 수급 이력과 후보를 재선정하거나 수정하지 않는다.
3. 승인된 코드에서 각각 아래 명령으로 계획을 검사한다. 이 문서 작성 중에는 실제 키로 실행하지 않았다.

   ```sh
   node --import tsx scripts/balta-ai-research.ts --phase=close --date=2026-10-26 --dry-run
   node --import tsx scripts/balta-ai-research.ts --phase=close --date=2026-10-28 --dry-run
   ```

4. 26일은 성과 신규 생성 0건이 기본 기대다. 이미 복원된 80건을 다시 계산해 쓰지 않는다.
   위 가격 불일치와 기타 부속 테이블 누락을 먼저 검토한다. run log 변경도 DB 쓰기 승인을 받는다.
5. 28일은 동결 후보만으로 최대 80개 성과 키를 검토한다. 가격 기준 충돌/휴장/거래정지/결측은 보류한다.

   **실제 계획의 테이블별 쓰기 수와 대상 키 범위를 확인한 뒤 그 범위로 별도 DB 쓰기 승인을 받는다.**

## 검증

- 운영 키 없이 in-memory 전송 계층으로 worker를 실행했다. 예상 밖 호스트/엔드포인트/메서드는 즉시 실패한다.
- 자정 경계, 실제 두 실패 run, 최초 생성일 고정 재실행, 금요일/토요일, 휴일, 날짜 오류,
  16:30 경계, 미검증 연도, 수동 날짜 누락, 원본 생성 메타데이터, 중복/통신 재시도,
  잘못된 저장 값, 가짜 저장 성공, 공급자 가격 재작성, 결측 가격, dry_run, KIS 토큰 만료를 검사한다.
- 전체 BALTA AI 테스트와 회원 계급 테스트 **119개 통과**, TypeScript 검사 통과, 신규 파일 lint 통과, Next production build 통과.
  환경 제한 안의 첫 빌드는 컴파일 단계에서 진행되지 않아 중지했고, 일반 로컬 권한 빌드는 통과했다.
  기존 middleware→proxy 변경 권고는 이번 범위에서 변경하지 않았다.
