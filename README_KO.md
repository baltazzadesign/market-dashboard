# baltatool 2.0 교체 패키지

메인 대시보드, 일별 분석, 로그인 화면을 같은 디자인으로 재구성한 업데이트입니다.
기존 Next.js 16.2.4 / React 19.2.4 / Recharts 구성과 package-lock.json을 사용합니다.

## 적용 순서

1. 현재 MARKET-DASHBOARD 프로젝트 폴더를 복사해 백업합니다.
2. 이 ZIP을 별도 폴더에 압축 해제합니다.
3. 압축 해제한 폴더 안의 app, components, lib, scripts 폴더와 루트 설정 파일을 현재 프로젝트 루트에 합쳐 덮어씁니다.
   프로젝트 루트는 기존 package.json이 있는 위치입니다.
4. 현재 프로젝트의 .env.local과 Vercel 환경변수, vercel.json, public 폴더는 현재 설정을 유지합니다.
   이번 패키지에는 운영 환경변수나 DB 파일이 들어 있지 않습니다.
5. 프로젝트 터미널에서 아래 명령으로 실행합니다.

```bash
npm ci
npm run dev
```

이미 같은 package-lock.json으로 의존성을 설치한 환경이라면 npm run dev부터 실행하면 됩니다.
화면을 확인한 다음 현재 사용하던 Git/Vercel 배포 방식으로 반영하세요.

```bash
npm run build
```

로그인은 기존 접근 코드로 가능합니다. 검증은 서버에서 수행하고 HttpOnly 쿠키로 24시간 유지합니다.
선택적으로 BALTATOOL_ACCESS_CODE 환경변수를 설정하면 해당 값이 기존 코드보다 우선합니다.
코드를 변경한 뒤에는 다시 로그인하세요.

## 화면 구성

- `/`: 지수·시장 폭·합산 수급 요약, 큰 주 차트, 비교 차트, 시장 브리핑, 투자자 수급, 신호 기록
- `/daily`: 날짜별 저장 기록, 여섯 지표의 연동 차트, 기록 요약과 데이터 표
- `/login`: 접근 코드 입력, 코드 표시/숨기기, Enter 제출, 오류 메시지, 로그인 진행 상태
- 공통: 어두운 배경과 민트 포인트, 상승 빨강·하락 파랑, 모바일 하단 메뉴

## 사용 방법

- 날짜 양옆 화살표로 전날·다음 날을 탐색하고 ‘오늘’로 돌아올 수 있습니다.
- 차트 탭에서 시장 폭, 시장점수, 수급, 지수, 비율, 가속도를 선택합니다.
- ‘전체 / 1시간 / 30분’ 또는 차트 드래그로 조회 구간을 바꿉니다.
- 차트 범례를 누르면 해당 선이 숨겨지거나 다시 표시됩니다.
- 신호 또는 표의 시간을 누르면 해당 시점 주변 1시간으로 차트가 이동합니다.
- 기록 표에서 시간·신호·내용을 검색하고 신호 강도, 시간순/최신순으로 정리할 수 있습니다.
- 상단 ‘내보내기’는 선택한 날짜의 전체 기록을 CSV로 저장합니다.
- 기록 표의 ‘CSV’는 현재 검색·필터·정렬을 반영한 모든 결과를 저장합니다.
- 설정에서 자동 갱신, 비교 차트, 차트 신호, 세로축, 새 강한 신호 알림을 조정합니다.
- 설정은 해당 브라우저에 저장됩니다. 차트 설정 초기화도 가능합니다.
- 알림은 브라우저 권한을 허용한 뒤, 화면 갱신 중 새로 감지한 최근 강한 신호에만 적용됩니다.
  처음 불러온 기록과 과거 날짜의 신호는 다시 알리지 않습니다.

## 데이터 연결 개선

1. **알림과 조회 날짜 통일**
   실제 `/api/market/alerts`와 예전 `/api/alerts` 주소를 모두 지원합니다.
   알림도 일별 데이터와 동일한 Supabase 기록에서 읽습니다.
   기존 SQLite alert_logs/signal_logs 테이블 유무 때문에 알림이 실패하던 경로를 정리했습니다.

2. **실시간 수집 경로**
   메인은 로그인 상태에서 `/api/market/refresh`를 POST로 호출합니다.
   서버가 기존 수집기에 CRON_SECRET을 전달하므로 비밀키를 브라우저에 전달할 필요가 없습니다.
   같은 서버 인스턴스의 동시 요청은 합치고 성공 응답은 30초 동안 재사용합니다.
   Vercel 전체 인스턴스에 걸친 전역 잠금은 아닙니다.
   `/api/cron` 역시 기존 수집기의 인증 검사를 거쳐 직접 연결합니다.

3. **기록의 시간과 누락 구분**
   수집 응답에 실제 처리 날짜와 시간을 추가했습니다.
   KST 기준 날짜를 사용하고, 분 단위 중복에서는 가장 최근 ID를 보존합니다.
   날짜 변경 시 이전 요청을 취소하고 늦게 도착한 이전 응답을 버립니다.
   누락된 시간은 차트에서 끊어 표시하며, 값을 보간하지 않습니다.

4. **수급 단위와 상태**
   기존 수집기는 이미 억원 단위로 변환해 저장합니다.
   화면과 CSV에서는 이를 다시 나누지 않습니다.
   없는 수급은 ‘—’, 정상적인 0은 ‘0’으로 구분합니다.
   직전값 유지·오류·출처 미확인 상태도 함께 보여줍니다.

5. **신호 표시의 의미**
   기존 일별 분석의 주요 임계값, 반등·다이버전스 조건을 공통 신호 모듈로 옮겼습니다.
   이전에 최근 70개 행에만 제한되던 분석을 선택 날짜의 전체 수신 기록에 적용합니다.
   저장 신호와 차트에서 계산한 신호를 구분하고 반복 신호를 정리합니다.
   ‘신뢰도 %’는 ‘조건 충족률’로 명칭을 바로잡았습니다.
   6개 조건인 다이버전스의 충족률은 6개를 분모로 계산합니다.
   확인되지 않은 수급이나 크게 끊긴 기록을 이용해 수급 다이버전스를 만들지 않습니다.
   이 비율은 백테스트로 검증된 수익 확률을 의미하지 않습니다.

6. **지수 등락 기준**
   기존 자료에 전일 종가가 없어 상단 등락률을 ‘직전 기록 대비’로 명시했습니다.
   KOSPI와 KOSDAQ은 차트에서 각각 별도의 세로축을 사용합니다.

## 검증 결과와 범위

- npm run build 성공: 메인, 일별 분석, 로그인 및 API 경로 생성 완료
- TypeScript 검사 통과
- 회귀 검증 12개 통과: KST 날짜 경계, 잘못된 날짜, 수급 단위·누락값,
  분 단위 중복, 장 초반 신호 보존, 알림 날짜·중복, 지연 상태,
  CSV 수식 문자열 처리, Supabase 날짜 조회, 로그인 쿠키, 수집 인증, Cron 인증
- 로그인 코드가 빌드된 브라우저 JavaScript에 포함되지 않는 것을 확인
- 기존 package-lock.json이 그대로 유지된 것을 확인

직접 실행할 수 있는 검증 명령:

```bash
node scripts/verify-market.cjs
```

검증에는 로컬 예시 데이터를 사용했고 실제 KIS/Supabase에 요청하지 않았습니다.
운영 API 키, DB 데이터, Vercel Cron 설정을 전달받지 않았으므로 실제 시세 수신과 배포는 확인하지 않았습니다.
브라우저 시각 검사와 모바일 실기기 테스트도 수행하지 않았습니다.
배포 전 기존 환경변수로 실행해 실제 시세·날짜별 기록·로그인을 확인하세요.

기존 middleware.ts 규칙은 Next.js 16에서 동작하지만 proxy 명칭으로 전환하라는 안내가 빌드에 표시됩니다.
기존 프로젝트에 적용하기 쉽도록 파일 이름은 유지했습니다.
AGENTS.md는 전달되지 않아 그 파일에만 적힌 별도 규칙은 확인하지 못했습니다.
