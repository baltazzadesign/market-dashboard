# 발타툴 세부 투자자 수급 업데이트

## 적용

아래 ZIP 3개를 모두 적용합니다. 각 ZIP에는 해당 폴더의 **내용물**이 들어 있습니다.

| 파일 | 압축을 풀어 나온 내용물을 넣을 위치 |
| --- | --- |
| app(2).zip | 프로젝트의 app 폴더 안 |
| components(2).zip | 프로젝트의 components 폴더 안 |
| lib(2).zip | 프로젝트의 lib 폴더 안 |

기존 폴더를 삭제하지 않고 같은 경로의 파일을 덮어씁니다. `app/app`, `components/components`, `lib/lib`처럼 이중 폴더를 만들지 않습니다. 예: 압축의 `api/market/live/route.ts`는 프로젝트의 `app/api/market/live/route.ts`입니다.

최상위 `package.json`이 있는 폴더에서 실행합니다.

```bash
npm run build
```

빌드가 성공하면 다음 명령을 실행합니다.

```bash
git add app components lib
git commit -m "Add detailed investor flow charts and storage"
git push
```

새 패키지나 환경변수는 없습니다. 기존 `logs.market_data` JSON 컬럼에 저장하므로, 이 컬럼을 사용하는 기존 수집이 정상이라면 추가 SQL 작업은 없습니다. 수집 스케줄과 인증 설정도 기존 것을 사용합니다.

## 어디서 보나요?

- 홈: 기존 수급 차트 아래의 **투자자 세부 수급**.
- 일별 분석: **투자자 세부 수급** 패널. 기존 시간 범위 선택과 연동됩니다.
- 수급 상세(`/flow`): 기본 수급 영역 아래의 **투자자 세부 수급**.
- 차트 전체보기: 상단 **세부 수급** 버튼. **기본 차트**를 누르면 기존 8개 차트로 돌아갑니다.
- 기록 탐색: **전체 기록 → 세부 수급 표시**를 누르면 합산 8개 항목과 세부 수집 상태가 추가됩니다.

합산 / KOSPI / KOSDAQ을 선택할 수 있습니다. 항목 버튼은 차트 표시 여부를 바꾸며, **모두 표시·모두 숨김**도 지원합니다. 기본 표시 항목은 금융투자·투신·사모·연기금입니다. 차트 위에 커서를 올리면 해당 시각의 값이 표시됩니다.

## 수집 필드

사용자가 제공한 `시장별 투자자매매동향(시세)[v1_국내주식-074]` 공식 Excel 문서의 순매수 **금액** 필드를 사용합니다. 수량 필드와 매수 총액을 섞지 않습니다.

| 표시 항목 | KIS 순매수 금액 필드 | 문서 명칭 |
| --- | --- | --- |
| 금융투자(증권) | scrt_ntby_tr_pbmn | 증권 |
| 투신 | ivtr_ntby_tr_pbmn | 투자신탁 |
| 사모 | pe_fund_ntby_tr_pbmn | 사모 펀드 |
| 은행 | bank_ntby_tr_pbmn | 은행 |
| 보험 | insu_ntby_tr_pbmn | 보험 |
| 기타금융(종금) | mrbn_ntby_tr_pbmn | 종금 |
| 연기금(기금) | fund_ntby_tr_pbmn | 기금 |
| 기타법인 | etc_corp_ntby_tr_pbmn | 기타 법인 |
| 별도 저장·세부 CSV | etc_orgt_ntby_tr_pbmn | 기타 단체 |

기금·기타 단체를 임의로 합치지 않습니다. 기관 총액은 기존 `orgn_ntby_tr_pbmn` 값을 유지하며 위 항목의 합계로 재계산하지 않습니다. 기타법인은 독립 항목으로 표시합니다.

기존 TR074(`FHPTJ04030000`) 호출 응답을 함께 읽습니다. KOSPI는 `KSP/0001`, KOSDAQ은 `KSQ/1001`이며 세부 수급을 위한 추가 API 호출은 없습니다.

## 값과 저장 기준

- 기존 수급과 동일하게 시장별 원본 금액을 100으로 나누고 정수로 반올림해 억원 단위로 표시합니다. 합산은 두 시장의 표시값을 더합니다.
- **제공된 Excel에는 원본 금액 단위가 명시되어 있지 않습니다.** 기존 변환 방식을 유지했으며 원본 금액도 함께 보관합니다. 실서비스 첫 수집 후 HTS eFriend Plus `[0403] 시장별 시간동향` 상단 표의 동일 시장·같은 시점 값과 금액 단위를 대조해야 합니다. 이번 검증은 공식 예제와 모의 응답으로 진행했으며 실제 계정의 실시간 수치는 대조하지 않았습니다.
- 한 시장의 해당 항목이 없으면 합산도 빈값입니다. 일부 항목만 있으면 있는 항목은 표시하고 상태를 `일부 항목 누락`으로 표시합니다.
- 실제 0은 `0`, 미수집·오류는 `—`입니다. 기존 세부 기록이 없는 과거 날짜를 0으로 채우지 않습니다.
- 기존 외국인·기관·개인의 직전값 유지 로직은 그대로 사용합니다. 새 세부 수급은 실패 시 직전값을 새 값처럼 복사하지 않습니다.
- 업데이트 후 기존 수집기가 성공적으로 수집·저장한 시점부터 쌓입니다. 과거 합산값만으로 세부 값을 복원하지 않습니다.
- 차트 시간은 앱의 수집 시각입니다. 이 API의 응답에 없는 체결 시각을 만들어 넣지 않습니다. 장후에도 API가 제공한 누적값을 기록하며 장후 거래만의 수급으로 해석하지 않습니다.
- 저장 위치: `logs.market_data.investorFlows`. 형식 버전, 수집시각, 표시단위, 변환계수, KOSPI/KOSDAQ/합산의 원본 금액·표시값·상태를 보관합니다.

## CSV

일반 기록 CSV는 기존 20개 열의 순서를 유지하고, 뒤에 합산 세부 8개 항목·세부 수집 상태·수집시각을 추가해 30개 열이 됩니다.

**세부 CSV**는 선택한 날짜의 전체 기록을 내보냅니다. 관측 시각마다 합산·KOSPI·KOSDAQ 3행씩 저장하고, 8개 항목과 기타 단체, 변환 전 원본 순매수 금액을 포함합니다. 화면의 항목 숨김이나 시간 확대 여부로 CSV가 잘리지 않습니다. 누락된 금액은 빈 셀입니다.

## 검증

- TypeScript 및 Next.js 프로덕션 빌드 성공.
- 공식 Excel 응답의 전체 필드 매핑, 금액/수량 구분, 0/누락/오류, 한 시장 실패, 이중 정규화, CSV 열 위치, 저장 요청 JSON 검증.
- 기존 버전과 정상 수집·실패 후 fallback 시 응답의 기존 수급·점수·신호 값이 동일한지 비교. 차트 범위/시장폭 점수 포함 15개 테스트 통과.
- 브라우저에서 홈·일별·수급 상세, 시장 전환, 8개 표시 버튼, 커서 읽기, 결측 선 끊기, CSV 다운로드, 기록표, 차트 보드 시간 범위와 모바일 화면 확인.

실제 KIS 인증정보 및 운영 DB에 접속하거나 배포하지 않았습니다. ZIP을 적용하고 배포한 뒤 수집된 값이 나타나는지 확인하세요.
