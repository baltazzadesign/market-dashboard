수집 상태 확인 패치

최신 제공 ZIP을 기준으로 2개 파일 수정, 진단 API 1개 추가. 기존 소스를 이후 별도로 수정했다면 덮어쓰기 전 차이를 확인하세요.

수정 내용
- DB 조회 HTTP 오류는 상태·오류 코드, 연결 실패는 오류 종류를 기록합니다. 인증키나 응답 원문은 새 진단 로그에 넣지 않습니다.
- 수집의 저장 실패와 전체 처리 실패는 HTTP 503, 장중 비정상 데이터 저장 생략은 502로 반환합니다. 정규장 외 정상 생략은 기존 200을 유지합니다.
- 시장폭 결측이어도 지수·수급 저장이 성공하면 200입니다.
- DB HTTP 오류에는 SUPABASE_HTTP_ERROR 로그를 추가하여 업종 저장 오류도 추적할 수 있습니다.
- 진단 URL: https://www.baltatool.com/api/market/collection-diagnostic?date=2026-09-14

진단 사용
배포한 뒤 로그인한 브라우저에서 진단 URL을 열고 JSON을 전달하세요. 완료된 분만 대조합니다.
missingBeforeFirst: 첫 저장 이전의 미수집 분
missingWithinObservedPeriod: 첫 저장 이후 DB에 없는 분
filtered: 원본은 있지만 현재 화면 필터에서 제외되는 분
flowUnavailable: 표시 대상 기록은 있지만 수급 수치가 없는 분
duplicates: 같은 분의 중복 행 (중복 자체가 누락을 뜻하지는 않습니다)

이 패치는 기존 누락 데이터를 복구하거나 시장폭 원본 0을 해결하지 않습니다. API 키·DB 스키마·cron 일정은 변경하지 않습니다.
실패 응답을 올바르게 반환하므로 실제 장애 시 cron-job.org에도 실패로 표시될 수 있습니다.

검증
TypeScript 변환 오류 없음. 모의 DB와 수집 응답으로 기록 없음/화면 제외/수급 결측 구분, 현재 분 제외, DB 오류 로그, 저장 실패 503, 결측 시장폭 정상 저장 200, 전체 처리 실패 503 확인.
전체 프로젝트 typecheck/build와 실제 운영 호출은 이 환경에서 실행하지 않았습니다. 배포 전 실행하세요.
